## مراجعة الإنتاج (Production Audit)
أداة بتقرا بس من ERPNext (مش بتغير أي حاجة) وبتراجع الإنتاج يوم بيوم من حركات Stock Entry نوعها Manufacture،
عشان تلاقي الأيام اللي متسجلش فيها إنتاج، أو صنف غلط، أو كمية غريبة، أو حركة اتسجلت متأخر.

```bash
npm run audit:production -- --from 2026-10-01 --to today
npm run audit:production -- --from 2026-09-01 --to 2026-09-30
```

- `--from` و `--to` بالشكل `YYYY-MM-DD`، و `today` = النهارده بتوقيت مصر (من غيرهم: من أول الشهر لحد النهارده).
- بيستخدم نفس مفاتيح ERPNext اللي في `.env.local`.
- الناتج في فولدر `reports/`: ملف `production-audit.md` (الملخص والتحذيرات وجدول يوم بيوم والتفاصيل) و `production-audit.csv` (جدول يوم بيوم، بيتفتح في Excel).
- ⚠️ فولدر `reports/` في `.gitignore` ومينفعش يترفع على GitHub لأن الريبو public.

## مراجعة الشهر: لقطة واحدة من ERPNext للتقريرين (Snapshot)
التقريرين اللي تحت (مطابقة الرصيد ومقارنة المنصرف) بيتعملوا من **لقطة واحدة** من ERPNext عشان أرقامهم تبقى من نفس اللحظة.
اللقطة فيها الحركات اللي تاريخها (posting_date) لحد `--to` بس (الافتراضي **امبارح** بتوقيت مصر)، وأي حركة بتاريخ النهارده مش بتتحسب خالص.

```bash
npm run audit:snapshot                                        # من أول الشهر لحد امبارح + التقريرين
npm run audit:snapshot -- --from 2026-10-01 --to 2026-10-25   # فترة معينة + التقريرين
npm run audit:stock                                           # مطابقة الرصيد بس، من آخر لقطة
npm run audit:issues                                          # مقارنة المنصرف بس، من آخر لقطة
```

- اللقطة بتتحفظ في `reports/snapshot-<وقت السحب>.json`، وأي تقرير ممكن يتعمل من لقطة معينة بـ `--snapshot reports/snapshot-….json`.
- أول كل ملف فيه "وقت سحب البيانات" والفترة، وقسم "حركات بتاريخ يوم X أو قبله بس اتسجلت بعده" (محسوبة، ومعروضة للعلم).
- لو ملف التقرير مفتوح في Excel أو قارئ PDF، بيتكتب نسخة جنبه باسم فيه وقت السحب.

## مطابقة رصيد مخزن المنتج التام مع الإكسيل (Stock Reconciliation)
بيطلع رصيد أول / الإنتاج / المنصرف / رصيد آخر من Stock Ledger Entry بنفس شكل الإكسيل بتاعنا،
وتفصيل المنصرف (تحميل للعربيات، مرتجع، مبيعات، جرد…)، والمقارنة مع الإكسيل، وأسباب كل فرق.

- بيشتغل من اللقطة (`npm run audit:snapshot` أو `npm run audit:stock`)، و `--match-from` = أول يوم نجربه لما ندور على تاريخ الإكسيل.
- أرقام الإكسيل في `reports/excel-input.json` (بيتعمل أول مرة، وبعد كده عدّل فيه الأرقام).
- الناتج: `reports/stock-reconciliation.md` و `.xlsx` و `.pdf` — ومينفعش يترفع على GitHub.

## مقارنة المنصرف يوم بيوم وعربية بعربية (Issue Comparison)
بيقارن إكسيل أذونات الصرف والإضافة + تقرير تحميل العربيات مع ERPNext على مستوى التاريخ × العربية × الصنف،
وبيصنّف كل فرق (ناقص في ERPNext / ناقص في الإكسيل / كمية غلط / يوم تاني / عربية غلط / صنف غلط / فاتورة بيع بدل تحويل / اتلغى)،
وبيقول إيه اللي محتاج يتصحح في ERPNext. قراية بس من ERPNext.

- بيشتغل من اللقطة (`npm run audit:snapshot` أو `npm run audit:issues`)، والفترة من اللقطة.
- حط الملفات في `reports/input/`: `azon.xlsx` (اذن الصرف / اذن الاضافة) و `tahmeel.xlsx` (شيت لكل يوم)، أو اديله المسار بـ `--azon` و `--tahmeel`.
- الناتج: `reports/issue-comparison.md` و `.xlsx` و `.pdf` — ومينفعش يترفع على GitHub (فيه أسماء المناديب).
